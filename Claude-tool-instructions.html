01 — passive, always on
Karpathy Guidelines
nothing to activate — works automatically every session
4 Rules It Enforces
1. Think before coding — plan first
2. Build simplest thing that works
3. Surgical changes only
4. Don't improve what wasn't asked
What It Prevents
x Refactoring files you didn't mention
x Adding features nobody asked for
x Over-engineering simple fixes
x Infinite loops with no exit criteria
// Prompts that work with it
Be specific about scope
"Fix the login bug in auth.js — don't touch anything else"
Define done explicitly
"Done = user can log in without 401 error. Stop after that."
Cybersecurity scripts
"Write a bash script to detect failed SSH logins. Only create detection.sh — don't modify any existing files."
If it feels too restrictive
"Refactor the entire auth module — this is intentional, not a bug fix."
It'll comply when you're explicit.

02 — 3 slash commands
Superpowers
brainstorm → write-plan → execute-plan. never skip steps.
1
/superpowers:brainstorm
Explores approaches, surfaces edge cases, asks clarifying questions. Use when you're not sure exactly what to build yet.
/superpowers:brainstorm build a CVE monitoring script that alerts on critical vulns
2
/superpowers:write-plan
Writes a full spec before touching any code. Defines files, functions, success criteria, edge cases. Review this carefully — it's your last cheap checkpoint.
/superpowers:write-plan
3
/superpowers:execute-plan
Executes the approved spec. Dispatches parallel sub-agents for independent tasks. Runs tests. Self-reviews. Only run after you've approved the plan.
/superpowers:execute-plan
// Real examples
Detection script
/superpowers:brainstorm SSH brute force detector /superpowers:write-plan // review spec /superpowers:execute-plan
App feature
/superpowers:brainstorm user auth system /superpowers:write-plan // edit spec if needed /superpowers:execute-plan
Security audit
/superpowers:brainstorm audit this codebase for vulns /superpowers:write-plan // confirm scope /superpowers:execute-plan
SIEM detection rule
/superpowers:brainstorm KQL rule for lateral movement /superpowers:write-plan // review logic /superpowers:execute-plan

04 — use 3 features, ignore 179
Everything Claude Code
CVE scanning · injection blocking · token optimization
1. CVE Scanning
Automatically checks every new dependency for known vulnerabilities. Runs silently — you only hear about it when something is flagged.
# Trigger manually on demand inside ds: "Scan all dependencies in this project for CVEs" # Or let it run automatically on every install # Already enabled: ds config set security.cve_scan true
2. Prompt Injection Blocking
Intercepts malicious strings in user input before they reach the model. Critical when your app takes external input and passes it to AI. Runs automatically.
# Test it manually inside ds: "Check this user input for prompt injection: [paste suspicious string]" # Already enabled: ds config set security.injection_guard true
3. Token Optimization
Compresses context before sending to the model. On large codebases cuts token bill roughly in half. Runs automatically once enabled.
# Already enabled if you ran: ds config set tokens.optimize true # Verify it's on: ds config get tokens.optimize

05 — parallel agent swarms
Ruflo
when one claude isn't enough — run a hundred

Ruflo runs multiple agents in parallel, each with a specific role, sharing memory. Instead of one agent doing everything sequentially — you get a development team.

// How to define a swarm
# 1. Create .claude/swarm.json in your project { "agents": [ { "role": "researcher", "task": "your research task" }, { "role": "writer", "task": "your build task" }, { "role": "reviewer", "task": "your review task" } ], "shared_memory": true } # 2. Run it: ds swarm run .claude/swarm.json
// Ready-to-use swarm configs
Detection Engineering Swarm
{ "agents": [ { "role": "researcher", "task": "map MITRE T1059.001 to detection opportunities" }, { "role": "writer", "task": "write SPL detection query for PowerShell abuse" }, { "role": "tester", "task": "validate query against sample logs in /logs" } ], "shared_memory": true }
Full App Feature Swarm
{ "agents": [ { "role": "backend", "task": "build the API endpoint and DB schema" }, { "role": "frontend", "task": "build the UI component for this feature" }, { "role": "tests", "task": "write unit and integration tests for both" } ], "shared_memory": true }
Security Audit Swarm
{ "agents": [ { "role": "scanner", "task": "scan all files for hardcoded secrets and CVEs" }, { "role": "reviewer", "task": "review auth logic for injection vulnerabilities" }, { "role": "reporter", "task": "compile findings into a structured report" } ], "shared_memory": true }
Job Hunting Swarm
{ "agents": [ { "role": "scraper", "task": "check LinkedIn + target company career pages for new roles" }, { "role": "matcher", "task": "match roles against resume in ~/vault/Job Search" }, { "role": "ranker", "task": "rank top 3 by fit score and flag application deadline" } ], "shared_memory": true }

Lets ds build brand new CLIs on demand in plain English. Without this, you have to run build commands manually.
