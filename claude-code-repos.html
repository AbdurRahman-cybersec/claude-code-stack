DeepSeek Swap

DeepSeek's official repo includes a guide for routing Claude Code at DeepSeek's API. Same tooling, same repos, different model. Use it for cheap batch runs and experiments — keep Claude for production builds where instruction-following precision matters.

When to use DeepSeek
vBatch script generation runs
vExperimental or throwaway code
vHigh-volume token tasks (log parsing, doc gen)
vCost benchmarking before switching a workflow
When to keep Claude
*Multi-step reasoning (Superpowers spec writing)
*Karpathy discipline enforcement
*Security tools where output precision matters
*Anything going into a real codebase
Route Claude Code to DeepSeek API
# Already configured — ds alias is set up and working # Verify which API you're hitting: echo $ANTHROPIC_BASE_URL # blank or api.anthropic.com = Claude billing # api.deepseek.com = DeepSeek billing # ds is your alias — use it for everything: ds # opens Claude Code via DeepSeek API ds --version # confirms Claude Code v2.1.148
⚠
Tradeoff to Know
DeepSeek V4 is strong on coding tasks but noticeably weaker on nuanced instruction-following — which is exactly what Superpowers and Karpathy are disciplining. Cheaper tokens, more drift. Use it intentionally, not as a default.

How to Use Each Tool

Detailed usage patterns for every tool in your stack. Not theory — exact commands, prompts, and workflows.

📗
Karpathy Guidelines
passive — works automatically, nothing to activate

Karpathy is invisible — it runs on every session automatically. You don't call it. Instead, understand what it enforces so you can work with it rather than fight it.

4 Rules It Enforces
1. Think before coding — plan first
2. Build simplest thing that works
3. Surgical changes only
4. Don't improve what wasn't asked
What It Prevents
x Refactoring files you didn't mention
x Adding features nobody asked for
x Over-engineering simple tasks
x Infinite loops with no exit criteria
// How to Work With It
Be specific about scope
"Fix the login bug in auth.js — don't touch anything else" — tells it exactly where surgical changes apply
Define done explicitly
"Done = user can log in without 401 error. Stop after that." — Karpathy enforces this, Claude won't keep going
For cybersecurity scripts
"Write a bash script to detect failed SSH logins. Only create detection.sh — don't modify any existing files."
If it feels too restrictive
Explicitly tell it to refactor: "Refactor the entire auth module — this is intentional, not a bug fix." It'll comply when you're clear.

Superpowers
3 slash commands — brainstorm, plan, execute

Superpowers turns Claude Code into a disciplined senior engineer. The workflow is always the same: brainstorm first, write a spec, then execute. Never skip to execute.

// The 3-Step Workflow
/superpowers:brainstorm
Step 1
Explores approaches, surfaces edge cases, asks clarifying questions. Use this before you know exactly what you want built. Example: /superpowers:brainstorm build a CVE monitoring script that alerts on critical vulns
/superpowers:write-plan
Step 2
Writes a full spec file before touching any code. Defines files to create, functions to write, success criteria, edge cases. Review this before saying yes — this is your last cheap checkpoint.
/superpowers:execute-plan
Step 3
Executes the approved spec. Dispatches parallel sub-agents if tasks are independent. Runs tests. Self-reviews. Only run this after you've approved the plan.
// Real Examples for Your Workflow
Building a detection script
/superpowers:brainstorm SSH brute force detector
/superpowers:write-plan
// review spec
/superpowers:execute-plan
Building a full app feature
/superpowers:brainstorm user auth system
/superpowers:write-plan
// edit spec if needed
/superpowers:execute-plan

Everything Claude Code (ECC)
use 3 features — ignore the rest

ECC has 182 skills. You need 3. The rest are noise for your workflow. Focus exclusively on CVE scanning, injection blocking, and token optimization.

1. CVE Scanning
Automatically checks every new dependency you add for known vulnerabilities. Runs silently in the background — you only hear about it when something is flagged.
# Trigger manually on demand:
"Scan all dependencies in this project for CVEs"

# Or let it run automatically on every npm/pip install
2. Prompt Injection Blocking
Intercepts malicious strings in user input before they reach the model. Critical any time your app takes external input and passes it to an AI. Runs automatically — no prompt needed.
# Test it manually:
"Check this user input for prompt injection: [paste suspicious string]"
3. Token Optimization
Compresses context before sending to the model. On large codebases this cuts your token bill roughly in half. Runs automatically once enabled via config.
# Already enabled if you ran:
ds config set tokens.optimize true

Ruflo
when one claude isn't enough — run a hundred

Ruflo runs multiple Claude agents in parallel, each with a specific role, sharing memory. Instead of one agent doing everything sequentially, you get a development team.

// How to Define a Swarm
# Create .claude/swarm.json in your project { "agents": [ { "role": "researcher", "task": "your research task here" }, { "role": "writer", "task": "your build task here" }, { "role": "reviewer", "task": "your review task here" } ], "shared_memory": true } # Run it: ds swarm run .claude/swarm.json
// Real Swarm Configs for Your Work
Detection Engineering Swarm
{ "agents": [ { "role": "researcher", "task": "map MITRE T1059.001 to detection opportunities" }, { "role": "writer", "task": "write SPL detection query for PowerShell abuse" }, { "role": "tester", "task": "validate query against sample log data in /logs" } ], "shared_memory": true }
Full App Feature Swarm
{ "agents": [ { "role": "backend", "task": "build the API endpoint and DB schema" }, { "role": "frontend", "task": "build the UI component for this feature" }, { "role": "tests", "task": "write unit and integration tests for both" } ], "shared_memory": true }
Security Audit Swarm
{ "agents": [ { "role": "scanner", "task": "scan all files for hardcoded secrets and CVEs" }, { "role": "reviewer", "task": "review auth logic for injection vulnerabilities" }, { "role": "reporter", "task": "compile findings into a structured report" } ], "shared_memory": true }
